# 새 작업 시작

1. **누구의 작업인지 확인**: `git config user.name`과 사용자의 설명으로 담당자를 정하고, 루트 `AGENTS.md` 3장의 담당 영역을 확인한다. 영역 밖이면 사용자에게 먼저 말한다.
2. **최신 코드 받기**: 작업 중인 변경이 없는지 `git status`로 본 뒤 `git switch main` → `git pull`. 변경이 남아 있으면 지우지 말고 사용자에게 어떻게 할지 묻는다.
3. **브랜치 만들기**: `git switch -c feat/<탭>-<내용>` (탭 이름: common, training, exam, store, ranking, me, content, ai).
4. **관련 문서 읽기**: 기획서에서 해당 기능 ID(예: T1)와 화면(예: S12), `docs/02` 테이블, `docs/03` API를 찾는다.
5. **계획 보여 주기**: 만들 파일 목록, 바뀌는 API·테이블, 확인 방법을 짧게 정리해 사용자에게 보여 주고 "이대로 진행할까요?"라고 묻는다. 파일 1~2개짜리 작은 수정은 바로 진행해도 된다.
6. 기획에 없거나 애매한 부분은 추측하지 말고 질문 하나로 묻는다.
