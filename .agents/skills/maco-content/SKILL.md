# 문제 은행 작성·검수

형식은 `docs/01_공통설계.md` 5-6장, 규칙은 `content/AGENTS.md`.

## 문제를 새로 쓸 때

1. 스킬(PHOTO, REVIEW)과 레벨(1~5)을 정하고, 기획서 5장 커리큘럼의 해당 레벨 목표 문장을 확인한다.
2. 유형을 고른다: `CHOICE2`(둘 중 고르기), `SPOT`(틀린 곳 찾기), `REWRITE`(고쳐 쓰기), `JUDGE`(상황 판단).
3. 코드: `<스킬>-<유형>-<세 자리 번호>`. `items.csv`의 같은 스킬·유형 마지막 번호 + 1.
4. 틀린 보기마다 `error_types.csv`의 코드를 하나씩 붙인다. 맞는 코드가 없으면 사용자(이동성)에게 새 오류 유형을 제안한다.
5. `explanation`(정답 이유 한 줄)과 `concept_card_id`를 채운다.
6. `init_difficulty`(1~5)를 붙인다. 1 = 거의 모두 맞힘, 5 = 대부분 틀림.

## 검수 체크리스트

- [ ] 정답이 하나로 분명한가 (선호형은 설문 결과가 있는가)
- [ ] 근거가 연구·플랫폼 가이드·설문 중 하나로 확인되는가
- [ ] 틀린 보기마다 오류 유형이 있고, 그 코드가 사전에 있는가
- [ ] 문장이 짧고 사장님 말투인가 (전문 용어는 풀어 썼는가)
- [ ] 이미지 사용 허락이 있고 개인정보가 가려졌는가
- [ ] 코드가 겹치지 않고, 기존 코드를 바꾸지 않았는가

AI로 문제 변형을 만들었다면 `active=false`로 넣고, 사람이 검수한 뒤 `reviewed_by`를 채우고 `true`로 바꾼다.
