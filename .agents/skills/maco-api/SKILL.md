# API 추가·변경

1. **규칙 확인** (`docs/01_공통설계.md` 4장)
   - 주소 `/api/v1/<복수 명사>`, 소문자-하이픈
   - 성공 `{ "data": ... }`, 실패 `{ "error": { "code": "대문자_스네이크", "message": "한국어" } }`
   - 필드 camelCase, 날짜 `2026-12-16`, 시각은 `+09:00`
   - 로그인이 필요한 API는 JWT 필요
2. **다른 탭이 쓰는 API인지 확인**: `docs/03`에서 사용하는 화면을 본다. 다른 담당자의 화면이 쓰면 바꾸기 전에 사용자에게 알리고, PR에 영향을 적는다.
3. **서버**: DTO `record`와 컨트롤러를 고친다. 새 에러는 `ErrorCode`에 추가한다.
4. **문서**: `docs/03_API설계_초안.md`의 해당 표 한 줄을 추가하거나 고친다.
5. **프론트 타입**: `frontend/src/lib/types/<탭>.ts`를 서버 DTO와 같게 맞춘다.
6. **확인**: 서버 실행 → `/swagger-ui`에서 성공·실패를 한 번씩 호출해 본다.
7. 이미 다른 사람이 쓰는 API를 없애거나 필드 이름을 바꾸는 일은 피한다. 꼭 바꿔야 하면 새 필드를 추가하고, 옛 필드는 상대가 옮긴 뒤 지운다.
