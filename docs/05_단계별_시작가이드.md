## STEP 2. GitHub 아이디 모으기 (전원 → 팀장)

- 각자 GitHub 아이디를 팀장에게 보낸다. 팀장은 STEP 3에서 초대와 담당자 설정(CODEOWNERS)에 쓴다.
- API 키(AI, 네이버, 카카오)는 **지금 모으지 않는다.** 필요한 사람만 나중에 받고, 채팅방에는 올리지 않는다.

## STEP 3. 팀 저장소 만들고 하네스 올리기 (팀장)

"하네스"는 4명의 AI 코딩 도구가 **같은 규칙으로 일하게 만드는 파일 묶음**이다 (자세한 설명: [04_AI코딩_하네스.md](04_AI코딩_하네스.md)).
이미 `Desktop\MACO\maco-repo-init` 폴더에 만들어 두었다. 이것을 GitHub 저장소의 첫 내용으로 올린다.

1. **저장소 만들기**: github.com → 오른쪽 위 **+** → **New repository**
   - Repository name: `maco`
   - **Private** 선택
   - "Add a README", .gitignore, license는 **모두 비워 둔다** (빈 저장소여야 한다)
   - **Create repository**
2. **내 컴퓨터로 받기**: GitHub Desktop → **File → Clone repository** → GitHub.com 탭에서 `maco` 선택
   - Local path: **`C:\dev\maco`** (영문 경로) → **Clone**
3. **하네스 파일 복사**: PowerShell에서 (또는 파일 탐색기로 `maco-repo-init` 안의 모든 파일·폴더를 `C:\dev\maco`로 복사)

```powershell
Copy-Item -Path "$env:USERPROFILE\Desktop\MACO\maco-repo-init\*" -Destination "C:\dev\maco" -Recurse -Force
```

   `.agents`, `.claude`, `.codex`, `.github`처럼 점(.)으로 시작하는 폴더도 함께 복사됐는지 확인한다.
4. **담당자 아이디 넣기**: `C:\dev\maco\.github\CODEOWNERS`를 VS Code로 열고 `@MINGUK`, `@SEUNGJUN`, `@MINHA`, `@DONGSEONG`을 실제 GitHub 아이디(`@아이디`)로 바꿔 저장한다. (VS Code에서 Ctrl+H로 한 번에 바꾸기)
5. **첫 커밋·올리기**: GitHub Desktop 왼쪽에 바뀐 파일 목록이 보인다.
   - 왼쪽 아래 Summary: `chore: 저장소 초기 설정과 AI 하네스`
   - **Commit to main** → 위쪽 **Publish branch** (또는 Push origin)
   - 이것이 **main에 직접 올리는 유일한 커밋**이다. 이후로는 모두 PR로 한다.
6. **팀원 초대**: github.com의 `maco` 저장소 → **Settings → Collaborators → Add people** → 3명의 아이디 입력 (권한 Write)
7. **확인**: 저장소의 **Actions** 탭에서 `ci`가 초록색 체크인지 본다.
8. (GitHub Pro가 있으면) **Settings → Branches → Add branch protection rule**
   - Branch name pattern: `main`
   - **Require a pull request before merging** → Required approvals: **1**
   - **Require status checks to pass** → `규칙 검사` 선택
   - Pro가 없으면 이 설정 대신 "main에 직접 올리지 않는다"를 팀 약속으로 지킨다.

## STEP 6. 로컬 DB 실행·규칙 검사 (전원)

1. **Docker Desktop을 먼저 실행**하고 "Engine running"이 될 때까지 기다린다.
2. PowerShell에서:

```powershell

```

```powershell

```


## STEP 7. 첫 작업: 뼈대 만들기 (담당별, 오늘 시작)

이제부터 실제 개발이다. 모든 작업은 **AI 도구에게 `maco-start` 스킬로 시작**한다. 순서가 중요하다: **서버 뼈대(박민하)와 화면 뼈대(주승준)가 먼저 합쳐져야** 다른 사람이 그 위에 만들 수 있다.

| 순서 | 담당 | 만들 것 | 브랜치 |
|---|---|---|---|
| 7-1 | 박민하 | 서버 뼈대 (Spring Boot 프로젝트, DB 연결, 응답 형식, AppClock) | `feat/common-backend-init` |
| 7-2 | 주승준 | 화면 뼈대 (Next.js 프로젝트, 5탭 빈 화면, 하단 탭 바) | `feat/common-frontend-init` |
| 7-3 | 이동성 | 문제 은행 CSV 양식 + 오류 유형 사전 초안 | `feat/content-format` |
| 7-4 | 강민국 | AI 모델 비교 테스트(D7), 네이버 검색 API 앱 등록, 연습 가게(카페) 자료 → 서버 뼈대가 합쳐지면 `AiClient` 스텁 | `feat/ai-client-stub` |

### 7-1. 서버 뼈대 (박민하)

1. 브라우저에서 **start.spring.io** 접속 후 아래처럼 고른다.
   - Project: **Gradle - Groovy** / Language: **Java**
   - Spring Boot: 기본으로 선택된 버전 (SNAPSHOT·M이 붙지 않은 것)
   - Group: `com.maco` / Artifact: `backend` / Name: `backend` / **Package name: `com.maco`**
   - Packaging: Jar / **Java: 21**
   - Dependencies (ADD DEPENDENCIES): **Spring Web, Spring Data JPA, MySQL Driver, Flyway Migration, Validation, Spring Security, Lombok, Spring Boot DevTools**
2. **GENERATE** → zip 받기 → 압축을 풀어 안의 내용물을 `C:\dev\maco\backend` 폴더에 넣는다. (`backend\gradlew`, `backend\build.gradle`이 보여야 한다. 이미 있는 `AGENTS.md`, `CLAUDE.md`는 그대로 둔다)
3. AI 도구에 요청:

```
/maco-start 서버 뼈대 작업이야. 나는 박민하. 브랜치는 feat/common-backend-init.
backend 폴더에 방금 Spring Initializr 프로젝트를 넣었어. docs/01_공통설계.md 1-2장, 3장, 4장, 5-1장 기준으로
1) .env 값으로 로컬 MySQL(docker-compose.yml)에 연결하는 설정,
2) 공통 응답 형식 {data}/{error}와 에러 처리,
3) com.maco.common.time.AppClock,
4) 일단 모든 API를 열어 두는 임시 보안 설정,
5) springdoc으로 /swagger-ui,
6) GET /api/v1/health 하나
를 만들어 줘. 계획부터 보여 주고, 내가 초보라서 각 파일이 무슨 역할인지도 설명해 줘.
```

4. 확인: 서버 실행 후 브라우저에서 `http://localhost:8080/swagger-ui`가 열리고 health API가 동작하면 완료.
   (Spring Security를 넣었기 때문에 처음에는 모든 주소가 로그인 화면으로 막힌다. 4)번 임시 보안 설정이 이것을 풀어 준다)

### 7-2. 화면 뼈대 (주승준)

1. `frontend` 폴더 안의 `AGENTS.md`, `CLAUDE.md`를 잠시 바탕화면으로 옮기고 `frontend` 폴더를 지운다 (빈 폴더여야 생성된다).


   질문 문구는 버전마다 다르다. **TypeScript, ESLint, Tailwind CSS, `src/` 폴더, App Router는 Yes**, 나머지는 기본값(Enter).
3. 옮겨 둔 `AGENTS.md`, `CLAUDE.md`를 `frontend` 폴더에 다시 넣는다.
4. AI 도구에 요청:

```
/maco-start 화면 뼈대 작업이야. 나는 주승준. 브랜치는 feat/common-frontend-init.
frontend에 방금 Next.js 프로젝트를 만들었어. docs/01_공통설계.md 1-1장과 5-5장, 기획서 9장 기준으로
1) 모바일 480px 가운데 정렬 레이아웃, 2) 하단 5탭 TabBar(트레이닝·시험·내 가게·랭킹·내 정보),
3) 각 탭의 빈 화면, 4) 디자인 토큰 초안(src/styles), 5) lib/api/client.ts 자리만
만들어 줘. 계획부터 보여 주고, 초보자도 이해하게 폴더 구조를 설명해 줘.
```

5. 확인: `cd frontend` → `npm run dev` → 브라우저 `http://localhost:3000`에서 하단 탭 5개가 눌리면 완료.

## STEP 8. 첫 PR 올리고 합치기

AI가 "완료"라고 해도 **직접 실행해서 확인한 뒤** 진행한다.

1. AI 도구에 `/maco-pr` (Codex는 "maco-pr 스킬대로 PR 준비해 줘") → 검사 실행, 커밋, PR 설명 초안까지 해 준다.
2. GitHub Desktop → 위쪽 **Push origin**
3. **Create Pull Request** 버튼 → 브라우저에서 PR 설명 붙여 넣기
   - 리뷰어는 **팀장 강민국**으로 자동 지정된다 (CODEOWNERS). 따로 지정하지 않아도 된다.
   - 강민국 본인의 PR은 리뷰 없이 병합할 수 있다.
4. 강민국은 자기 AI 도구에 `/maco-review` + PR 주소를 주고 함께 확인한 뒤, GitHub에서 **Approve**
5. CI가 초록색이고 승인이 있으면 PR을 올린 사람이 **Squash and merge**
6. 합쳐진 뒤 **모두**: GitHub Desktop → Current branch를 `main`으로 → **Fetch origin → Pull origin**

## STEP 9. 매일 개발 루틴

1. Docker Desktop 실행 → GitHub Desktop에서 `main` **Pull**
2. 새 브랜치 (`feat/<탭>-<내용>`) — GitHub Desktop: Current branch → **New branch**
3. AI 도구 새 대화 → `/maco-start` + 오늘 만들 것 (기능 ID와 화면 번호를 함께, 예: "T1 쪽지시험, 화면 S12")
4. AI가 보여 주는 **계획을 읽고** 이해가 안 되면 "초보자에게 설명하듯 다시 말해 줘"
5. 작게 만들고 자주 실행해 본다. 에러가 나면 **에러 전문**을 붙여 넣는다.
6. 하루에 PR 하나 이상 (`/maco-pr`)
7. 매주 금요일(12/5, 12/12) 팀장이 전체를 합쳐 시연 흐름을 확인한다.

### AI 코딩할 때 꼭 지킬 것

| 하기 | 하지 않기 |
|---|---|
| 한 번에 기능 하나만 시키기 | "앱 전체 만들어 줘" 같은 큰 요청 |
| 계획을 먼저 보고 진행 | 이해 못 한 큰 변경을 그대로 PR |
| "이 코드가 무슨 일을 하는지 설명해 줘"로 배우기 | `.env` 내용이나 키를 대화창에 붙여 넣기 |
| AI가 완료라고 해도 직접 실행 확인 | 다른 사람 담당 폴더 고치기 |
| 대화가 길어지면 새 대화로 시작 (사용량 절약) | `main` 브랜치에서 바로 작업 |
