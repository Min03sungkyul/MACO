# 07. 프로토타입 기반 개발 계획

> 기준: 주승준의 시연 프로토타입(`chore/prototype-demo` 브랜치, PR #1의 `prototype/` 폴더)과 그 안의 `MIGRATION.md`, `docs/api-contract.md`.
> 팀 문서(`docs/01`~`03`)와 프로토타입이 다르면 **팀 문서가 기준**이다. 바꾸려면 4장처럼 팀이 정하고 팀 문서를 고친다.
> 작성: 강민국 (2026-11-27). 기능 동결 12/11, 발표 12/16.

## 0. 한눈에 보기

- 프로토타입은 시연 9단계를 **서버 없이 화면만으로** 끝까지 돌린다. 화면 흐름, 문구, 계산 규칙은 그대로 가져오고, **코드는 팀 구조로 다시 쓴다.**
- 이 문서는 네 가지를 정리한다.
  1. 파트별로 무엇을 옮기고 만들지 (1장)
  2. 프로토타입에 없어서 **새로 넣은 일** (2장, 표에 ★)
  3. 팀 규칙에 맞게 **바꾼 점** (3장)
  4. 프로토타입과 팀 문서의 숫자가 달라 **팀이 정해야 할 것** (4장)

### 3-1. 프로토타입에서 더 좋아서 그대로 가져오는 것

- **틀린 곳 찾기를 좌표 없이 만들기:** 프로토타입은 캡처에서 읽은 값으로 플레이스 화면을 다시 그리고, 문제 있는 줄을 탭하게 한다. 이렇게 하면 AI가 좌표를 줄 필요가 없다. `docs/01` 8장 5번("AI가 좌표까지 줄지")은 **이 방식으로 정하는 것을 제안한다** (강민국 결정, 12/3 기한).
- **규칙 채점 = FALLBACK:** AI가 실패해도 루브릭 규칙 채점과 상황극 대본으로 화면이 끝까지 동작한다. AGENTS 4장 ②의 "FALLBACK이어도 동작"을 바로 만족한다.
- **잘한 점 먼저, 고칠 점은 하나만**이라는 피드백 문장 원칙, 진단 카드를 점수 낮은 순서로 보여 주는 규칙.

## 4. 팀이 정할 숫자 (프로토타입 ≠ 팀 문서)

모두 가정값이다. **12/2 첫 통합 전까지** 정하고, 정한 값으로 `docs/01`과 코드 상수를 함께 고친다.

| 항목 | 프로토타입 | `docs/01` | 제안 | 정할 사람 |
|---|---|---|---|---|
| 사용자 갱신 폭 K_u | 0.4 고정 | 0.4 / (1 + 0.05·푼 문제 수) | `docs/01` (많이 풀수록 덜 흔들림) | 박민하 |
| 문제 갱신 폭 K_i | 0.15 | 0.1 | 0.1 | 박민하 |
| θ 시작값 | −1 | 0 (배치 테스트로 조정) | 0 | 박민하 |
| 난이도 초깃값 | 레벨 1·3·5 → −1·0·+1 | 1~5 → −2~+2 | `docs/01` (CSV `init_difficulty` 1~5) | 박민하·이동성 |
| 스킬 레벨 기준 θ | −0.5 / 0 / 0.5 / 1 | −1 / −0.3 / 0.3 / 1 | 프로토타입 (예시 계정·4주 넘기기가 이 값으로 맞춰져 있음) | 박민하 |
| 레슨 문제 수 | 6 | 7 (복습 2 포함) | 7 | 주승준 |
| 고쳐 쓰기 정답 기준 | 75점 | 70점 | 70 | 강민국·주승준 |
| 사진 미션 통과 | 밝기 85~215, 선명도 6 이상 | 없음 | 프로토타입 값을 가정값으로 추가 | 강민국 |
| 오류 유형 개수 | 18개 (사진 7, 답글 11) | 14개 초안 | 이동성이 합쳐서 확정 | 이동성 |
