# 02. 데이터 설계 (DB 초안)

> MySQL 8, 문자셋 utf8mb4, 시간대 Asia/Seoul. 테이블·컬럼은 snake_case.
> 모든 테이블에 `id BIGINT AUTO_INCREMENT`(복합 키 테이블 제외), `created_at`, 필요하면 `updated_at`.
> **P0** = 프로토타입에 꼭 필요, **P1** = 여유 있으면. 숫자는 가정값이다.

## 0. 전체 그림

```
users ─┬─ user_skill ── skill ── item ── item 보기(choices_json)·hotspot
       ├─ attempt ─────────────┘          └─ error_type (오류 유형 사전)
       ├─ wrong_note
       ├─ lesson_session ── lesson ── concept_card
       ├─ quiz ── (quiz 안 문제는 attempt로 기록)
       ├─ roleplay_session ── roleplay_scenario ── rubric
       ├─ xp_log, daily_goal, streak, user_badge
       ├─ league_member ── league_group
       ├─ region
       └─ store ─┬─ capture ── gate_check
                 ├─ spot_game
                 ├─ mission_submission ── mission
                 └─ review_card, review_request_log
ai_log, ai_cache (AI 모듈)
```

## 1. 사용자·공통 (박민하)

| 컬럼 | 타입 | 설명 |

| email | VARCHAR(255) UNIQUE NULL | 이메일 로그인용 (시연 계정) |
| password_hash | VARCHAR(100) NULL | BCrypt |
| provider | ENUM('EMAIL','KAKAO','NAVER') | |
| provider_user_id | VARCHAR(100) NULL | 소셜 로그인 식별값. (provider, provider_user_id) UNIQUE |
| nickname | VARCHAR(30) | 랭킹 표시 이름 |
| mode | ENUM('LEARNING','STORE') | 학습 모드 / 내 가게 모드 |
| store_type | VARCHAR(20) | 관심 업종 (CAFE …), 학습 모드의 연습 가게 결정 |
| daily_goal_xp | INT | 30 / 60 / 120 |
| habit_cue | VARCHAR(50) NULL | 습관 고리 ("마감 정리 후") |
| region_id | BIGINT NULL | 랭킹 지역 (내 가게 모드는 매장 주소에서 자동) |
| ranking_visibility | ENUM('PUBLIC','FRIENDS','PRIVATE') | 기본 PUBLIC |
| league_enabled | BOOLEAN | 리그 끄기 (기본 true) |
| placement_done | BOOLEAN | 배치 테스트 완료 여부 |
| is_demo | BOOLEAN | 시연 계정 |

### region — P0

| 컬럼 | 설명 |

| sido, sigungu | "인천광역시", "부평구" |

MVP는 인천·서울 구 단위만 넣는다.

## 2. 콘텐츠 (이동성 작성·검수, CSV에서 적재)

### skill — P0
`code`(PK: INFO, PHOTO, REVIEW, COPY, PROMO, ADS), name, gate ENUM('FIND','TRUST','NOTIFY'), unit_order, can_lv1·can_lv3·can_lv5(레벨별 "할 수 있다" 문장), ready(문제가 있는 유닛)

### concept_card — P0
skill_code, level(1~5), title, body(TEXT), evidence(근거 한 줄), image(선택)

### lesson — P0
skill_code, level, seq(경로 순서), title, concept_card_id, item_count(기본 7)

### error_type — P0 (오류 유형 사전)

| 컬럼 | 설명 |
|---|---|
| code | PK (예: `REPLY_NO_EMPATHY`) |
| skill_code | |
| name | "공감 없음" |
| description | 무엇이 문제인지 |
| fix_tip | 고칠 점 한 줄 (AI가 실패했을 때 대신 보여 줄 문장) |
| evidence | 근거 연구·가이드 |

### item — P0 (문제 은행)

| 컬럼 | 타입 | 설명 |
|---|---|---|
| code | VARCHAR(40) UNIQUE | `PHOTO-CHOICE2-007` |
| skill_code | | |
| type | ENUM('CHOICE2','SPOT','REWRITE','JUDGE') | 둘 중 고르기 / 틀린 곳 찾기 / 고쳐 쓰기 / 상황 판단 |
| kind | ENUM('RULE','PREFERENCE') | 규칙형 / 선호형 |
| mode_scope | ENUM('BOTH','LEARNING','STORE') | |
| store_type | VARCHAR(20) NULL | 업종 팩 (NULL이면 공통 코어) |
| prompt | TEXT | 문제 문장 |
| context | TEXT NULL | 고쳐 쓰기의 손님 리뷰 등 문제 상황 |
| media | VARCHAR(255) NULL | 이미지 경로. 틀린 곳 찾기는 `view:grid\|reviews\|reply` |
| choices_json | JSON | `[{"key":"A","text":"…","image":"…","errorType":"PHOTO_DARK"}, …]` (정답 보기는 errorType 없음) |
| answer | VARCHAR(20) | 정답 보기 키 (SPOT은 핫스팟 id 목록, REWRITE는 NULL) |
| rubric_code | NULL | REWRITE 채점 기준 |
| sample_answer | TEXT NULL | REWRITE 예시 한 줄 (채점 뒤에만 보여 준다) |
| explanation | TEXT | 정답 이유 한 줄 |
| concept_card_id | | 30초 원리 카드 |
| init_difficulty | TINYINT | 1~5 (검수자가 붙임) |
| difficulty | DOUBLE | Elo 난이도 d (풀릴 때마다 갱신) |
| attempt_count | INT | |
| active | BOOLEAN | |

### hotspot — P0
owner_type ENUM('ITEM','PRACTICE_SCREEN','CAPTURE'), owner_code(문제 코드 등), part_key, seq, label(글 또는 그림 스펙), stars(리뷰 조각), bad(틀린 곳인지), error_type_code, reason, x, y, w, h(이미지 대비 %, 격자·목록 조각이면 비움). (owner_type, owner_code, part_key) UNIQUE

### rubric — P0
code, criterion_key(EMPATHY …), seq, criterion("공감"), weight, description, good(잘한 점 문장), fix(고칠 점 문장), error_type_code. (code, criterion_key) UNIQUE

### roleplay_scenario — P0 (MVP 1종: 불만 리뷰 손님)
code, skill_code, title, persona(TEXT), opening_line, max_turns(3), rubric_code, mode_scope

### practice_store — P0 (MVP: 카페 1개)
code, store_type, name, place_image, insta_image, menu_json, reviews_json, gate_preset_json(연습 가게의 관문 점수)

## 3. 학습 기록·Elo (박민하 엔진, 트레이닝·시험이 씀)

### user_skill — P0
PK(user_id, skill_code), theta DOUBLE(기본 −1.2, docs/01 5-3), level TINYINT, attempt_count, correct_count, updated_at

### attempt — P0 (모든 풀이 한 줄씩)

| 컬럼 | 설명 |
|---|---|
| user_id, item_id | |
| context | ENUM('PLACEMENT','LESSON','QUIZ','WRONG_NOTE','UNIT_TEST') |
| session_id | lesson_session / quiz id |
| answer | 사용자 답 (REWRITE는 TEXT 별도 컬럼 `answer_text`) |
| correct | BOOLEAN |
| score | REWRITE 채점 점수 0~100 (NULL 가능) |
| error_type_code | 틀렸을 때 고른 보기의 오류 유형 |
| elapsed_ms | |
| p_expected | 출제 시 예측한 맞힐 확률 (연구 분석용) |
| theta_before, theta_after | |
| attempt_date | **가상 날짜 기준** 날짜 (AppClock) |

### wrong_note — P0
PK(user_id, item_id), wrong_count, review_step(0·1·2), last_wrong_date, next_review_date, resolved BOOLEAN

복습 간격(가정): 틀린 다음 날 → 3일 뒤 → 7일 뒤, 맞히면 다음 단계, 두 번 연속 맞히면 resolved.

### lesson_session — P0
user_id, lesson_id, item_ids_json(낸 문제), started_at, finished_at, correct_count, total_count, xp_gained

## 4. 시험 (이동성)

### quiz — P0
user_id, kind ENUM('DAILY','UNIT'), quiz_date, item_ids_json, score(0~100), submitted_at. (user_id, kind, quiz_date) UNIQUE — 쪽지시험은 하루 1번

### roleplay_session — P0
user_id, scenario_id, turns_json(`[{"role":"customer","text":"…"},{"role":"owner","text":"…"}]`), status ENUM('IN_PROGRESS','DONE'), rubric_scores_json, total_score, report_json(잘한 점·고칠 문장 3개), xp_gained, ai_source(LIVE/RECORDED…)

## 5. 점수·꾸준함·랭킹 (박민하)

### xp_log — P0
user_id, reason(XpReason), amount, source_key, xp_date(가상 날짜), created_at. (user_id, source_key) UNIQUE — 중복 적립 방지

### daily_goal — P0
PK(user_id, goal_date), goal_xp, earned_xp, training_seconds, solved_count, achieved BOOLEAN, busy_kept BOOLEAN(바쁜 날 2분 복습으로 채운 날)

### streak — P0
user_id PK, current_days, best_days, last_achieved_date, bonus_given_date(7일 연속 보너스를 준 날)

### badge / user_badge — P1
badge: code, name, condition. user_badge: user_id, badge_code, earned_at

### league_group / league_member — P0

| 테이블 | 컬럼 |
|---|---|
| league_group | week_start(월요일), tier(1~5), size(30) |
| league_member | group_id, user_id, weekly_xp, rank, result ENUM('PROMOTE','STAY','DEMOTE') NULL |

- 그 주에 일일 목표를 처음 채운 사용자를 같은 tier의 빈 그룹에 넣는다.
- 월요일 0시(가상 날짜 기준) 마감: 상위 7명 승급, 하위 5명 강등.
- 시연용 가상 사용자는 `users.is_demo = true` + 미리 만든 xp_log로 채운다.

### 지역 랭킹 — 테이블 없음 (집계 쿼리)
그 주 `xp_log`를 region별로 합산해 순위. 화면에는 내 순위, 상위 10명, 바로 위·아래만 보낸다. 사용자 수가 늘면 주간 결과 테이블을 추가한다.

### friend — P1
user_id, friend_id, status ENUM('PENDING','ACCEPTED'), invite_code(users에 별도 컬럼)

## 6. 내 가게 (강민국)

### store — P0 (계정당 1개)
user_id UNIQUE, name, category, address, road_address, region_id, naver_link, mapx, mapy, verified BOOLEAN(P2, 매장 인증)

### capture — P0
store_id, platform ENUM('PLACE','INSTA'), image_path, status ENUM('UPLOADED','READ','CONFIRMED','FAILED'), ai_read_json(AI가 읽은 값), confirmed_json(사장님이 확인·수정한 값), ai_source

### gate_check — P0
store_id, check_date, place_capture_id, insta_capture_id, find_score, trust_score, notify_score(0~100), find_passed, trust_passed, ad_unlocked BOOLEAN, findings_json(진단 카드: 항목·상태·이유·추천 레슨)

관문 규칙(어떤 값이면 몇 점인지)은 코드의 규칙표로 두고, 기준값은 가설로 표시한다.

### spot_game — P0
user_id, source ENUM('CAPTURE','PRACTICE'), source_id, hotspot_ids_json, found_ids_json, finished_at

### mission / mission_submission — P0 (MVP 미션 1종)

| 테이블 | 컬럼 |
|---|---|
| mission | code, skill_code, gate, title, description, unlock_level, submit_type ENUM('PHOTO','TEXT'), rubric_code, mode_scope |
| mission_submission | user_id, mission_id, text, image_path, feedback_json, score, passed BOOLEAN, ai_source, submitted_at |

### review_card / review_request_log — P0
review_card: store_id, message(대가 없는 요청 문구), qr_target_url, design. review_request_log: store_id, log_date, count

### ad_experiment — P1
store_id, channel, budget, stop_rule, start_date, end_date, result_json

## 7. AI (강민국)

### ai_cache — P0
cache_key(task + 입력 해시) UNIQUE, task, output_json, model, created_at, hit_count

### ai_log — P0
user_id NULL, task, model, source(LIVE/CACHE/RECORDED/FALLBACK), input_tokens, output_tokens, cost_usd DECIMAL(10,6), latency_ms, ok BOOLEAN, error_code

### ai_recorded — P0 (시연용 저장 응답)
task, match_key(시연 입력 식별값), output_json — `AI_MODE=recorded`일 때 여기서 꺼낸다
