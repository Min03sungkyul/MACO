# 04. AI 코딩 하네스

> 팀원 4명 모두 AI 코딩 도구로 개발한다 (Claude Code 3명, Codex 1명). 도구가 달라도 **같은 규칙·같은 절차·같은 검사**로 일하도록 만든 파일 묶음을 "하네스"라고 부른다.
> 하네스는 팀장(강민국)의 Claude Code 환경을 기준으로 만들었고, Codex도 같은 규칙을 읽도록 맞췄다. 하네스 담당: 강민국.
> 실제 파일은 `Desktop\MACO\maco-repo-init`에 있고, [05_단계별_시작가이드.md](05_단계별_시작가이드.md) STEP 3에서 저장소에 올린다.

## 1. 왜 필요한가

- AI는 규칙을 알려 주지 않으면 사람마다 다른 방식으로 코드를 만든다. 4명이 합치는 순간 충돌한다.
- 공통 모듈 약속(AppClock, XpService, SkillService, AiClient)을 어기면 시연 핵심 장면("4주 넘기기", XP, AI 저장 응답)이 깨진다.
- 초보 팀이므로 **AI가 스스로 규칙을 지키게 하고, 못 지키면 검사가 잡게** 한다.

## 2. 구성 (3겹)

| 겹 | 파일 | 하는 일 | Claude Code | Codex |
|---|---|---|---|---|
| ① 규칙 | `AGENTS.md` (루트), `frontend/` `backend/` `content/`의 `AGENTS.md` | 프로젝트 설명, 담당 영역, 꼭 지킬 규칙 10개, 작업 방식, 명령어, 완료 기준 | `CLAUDE.md`가 `@AGENTS.md`로 불러옴 | 자동으로 읽음 |
| ② 절차 | 스킬 7개: 원본 `.agents/skills/`, 복사본 `.claude/skills/` | 작업 시작, 기능 만들기, API, 문제 은행, AI 기능, PR, 리뷰 순서 | `/maco-start`처럼 호출 | `.agents/skills` 자동 인식 (안 보이면 SKILL.md를 읽게 함) |
| ③ 검사 | `scripts/check-rules.mjs`, `.github/workflows/ci.yml`, PR 템플릿, CODEOWNERS | 규칙 위반 자동 검사, 빌드·테스트, 담당자 리뷰 요청 | 같음 | 같음 |
| 안전 | `.claude/settings.json`, `.codex/config.toml` | `.env` 읽기 금지, force push·`main` 직접 push 금지, 저장소 밖 수정 금지 | 권한 설정 | 샌드박스·승인 설정 |

AI 도구가 무엇이든 ③ 검사는 GitHub에서 똑같이 돈다. 규칙을 어긴 PR은 빨간 X가 떠서 합칠 수 없다.

## 3. 규칙 검사가 잡는 것 (`node scripts/check-rules.mjs`)

| 검사 | 결과 |
|---|---|
| `.env` 파일 커밋, API 키처럼 보이는 문자열 | ❌ 오류 |
| backend에서 `LocalDate.now()` 등 직접 사용 (AppClock 밖) | ❌ 오류 |
| `com.maco.ai` 패키지 밖에서 AI 회사 API·SDK 사용 | ❌ 오류 |
| `ddl-auto=update` | ❌ 오류 |
| 이미 병합된 마이그레이션 파일 수정 | ❌ 오류 |
| 스킬 원본과 복사본이 다름 | ❌ 오류 |
| 화면 코드에 색 코드(`#ffffff`) 직접 사용 | ⚠️ 경고 |
| 문서·CSV에 `\uXXXX` 유니코드 이스케이프 | ⚠️ 경고 |

XP·SkillService·패키지 경계 규칙은 자동 검사가 어려워 **짝 리뷰(`maco-review`)**로 확인한다.

## 4. 스킬 7개

| 스킬 | 언제 | 핵심 |
|---|---|---|
| `maco-start` | 새 작업 시작 | 담당 확인 → main 최신 → 브랜치 → 문서 읽기 → 계획 확인 |
| `maco-feature` | 탭 기능 만들기 | 테이블 → 엔티티 → service(공통 모듈) → API → 타입 → 화면 → 검사 |
| `maco-api` | API 추가·변경 | 서버 DTO, `docs/03`, `lib/types`를 함께 맞춤 |
| `maco-content` | 문제 은행 작성·검수 | 코드 규칙, 오류 유형, 근거, 검수 체크리스트 |
| `maco-ai-task` | AI 기능 추가 | 프롬프트 파일, 형식 검사, FALLBACK, 캐시, 저장 응답, 비용 메모 |
| `maco-pr` | 커밋·PR | 검사 실행 → 변경 확인 → 커밋 → PR 설명 초안 (push는 요청할 때만) |
| `maco-review` | 짝 PR 리뷰 | 동작 → 공통 규칙 → 시연 영향 → API → 화면 |

## 5. 개인 설정과 팀 설정 구분

| 팀 설정 (저장소에 커밋) | 개인 설정 (커밋하지 않음) |
|---|---|
| `AGENTS.md`, `CLAUDE.md`, 스킬, `.claude/settings.json`, `.codex/config.toml` | `.claude/settings.local.json`, `~/.claude/` 전역 설정, `~/.codex/config.toml`, 사용 모델 선택 |

- 개인적으로 편한 설정(테마, 모델, 추가 허용 명령어)은 개인 설정에만 둔다.
- 팀 규칙에 넣고 싶은 것이 생기면 팀장에게 말하고 PR로 바꾼다.

## 6. 하네스 고치는 방법 (팀장)

1. 규칙은 `AGENTS.md`만 고친다 (`CLAUDE.md`에는 Claude 전용 내용만).
2. 스킬은 `.agents/skills/<이름>/SKILL.md`만 고치고 `node scripts/sync-skills.mjs` 실행 → 복사본이 맞춰진다.
3. 새 규칙이 자동 검사 가능하면 `scripts/check-rules.mjs`에 추가한다.
4. PR 제목은 `chore(harness): ...`. 합친 뒤 팀 채팅에 "하네스 바뀜: 무엇이"를 알린다. 팀원은 Pull 후 AI 도구에서 **새 대화**를 시작해야 바뀐 규칙이 적용된다.

## 7. 도구별 메모

- **Claude Code**: Windows에서는 Git이 설치되어 있어야 한다. 데스크톱 앱(Code 탭)과 터미널(`claude`) 모두 같은 하네스를 읽는다. 파일 3개 이상 바꾸는 작업은 Plan 모드를 쓴다.
- **Codex**: 프로젝트를 **신뢰(trust)**로 등록해야 `.codex/config.toml`이 적용된다. 스킬은 `.agents/skills`에서 읽는다. Codex 사용자는 짝 리뷰 때 Claude 사용자와 같은 체크리스트(`maco-review`)를 쓴다.
- 도구가 업데이트되며 파일 위치 규칙이 바뀔 수 있다. 스킬이 안 보이면 AI에게 "`.agents/skills/maco-start/SKILL.md`를 읽고 따라 해 줘"라고 직접 말하면 된다.
